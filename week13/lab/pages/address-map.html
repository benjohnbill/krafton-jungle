IP는 컴퓨터 번호도, 사이트 번호도 아님

내 PC(WSL)에서 조회한 실제 값으로 그린 주소 지도 · IP는 인터페이스에, 이름은 바깥 명부에, 사이트는 Host 줄에

1. 컴퓨터 → 인터페이스 → IP

여기까지는 트리 · IP는 컴퓨터가 아니라 인터페이스(연결 지점)에 붙음

내 PC (WSL)
├─ lo  루프백, 밖으로 안 나감
│   ├─ 127.0.0.1/8
│   ├─ 10.255.255.254
│   └─ ::1
├─ eth0  WSL 가상 네트워크
│   ├─ 172.25.165.29
│   └─ fe80::…
└─ tailscale0  Tailscale VPN
    ├─ 100.x.x.x
    └─ fd7a:…

인터페이스 하나에 IP 여럿 · 컴퓨터 하나에 인터페이스 여럿 · /8 = 127.x.x.x 전체가 lo · fe80:: = 같은 링크 안에서만 쓰는 IPv6.

2. 이름 → IP

트리가 아니라 명부 · 이름은 컴퓨터 안이 아니라 /etc/hosts와 DNS에 적힘

명부이름IP
/etc/hostslocalhost127.0.0.1
/etc/hostsPC 이름127.0.1.1 (이것도 lo)
DNSexample.com172.66.147.243 · 104.20.23.154 · IPv6 둘

이름 하나 → IP 여럿(example.com) · IP 하나 → 이름 여럿도 가능 → 그물. DNS에 묻는 것은 IP뿐, 포트는 URL이 정함.

3. 문은 여럿, nginx는 하나

nginx가 0.0.0.0:80에서 listen → 모든 인터페이스의 모든 IPv4 주소로 같은 nginx에 도착

127.0.0.1:80       lo
172.25.165.29:80   eth0
100.x.x.x:80       tailscale0
       │
       ▼
nginx 프로세스 하나
listen 0.0.0.0:80 · [::]:80
보낸 요청도착한 IP결과
curl http://127.0.0.1/127.0.0.1200
curl http://172.25.165.29/172.25.165.29200
curl http://100.x.x.x/100.x.x.x200

4. IP는 어느 문, Host는 어느 사이트

IP는 연결할 때 이미 씀 · 사이트 이름은 요청 텍스트 안의 Host 줄로 따로

TCP 연결

connect(127.0.0.1:80)
# 어느 컴퓨터의 어느 문

HTTP 요청 텍스트

GET / HTTP/1.1
Host: blog.test
# 그 문 안의 어느 사이트
보낸 요청Host 줄결과
curl http://127.0.0.1/127.0.0.1200
curl -H 'Host: blog.test' http://127.0.0.1/blog.test200

지금 설정은 server_name _; 하나 = 어떤 Host든 같은 사이트 → blog.test도 200. Host별 server 블록을 더 두면 127.0.0.1 하나에 사이트 여럿. HTTP/1.1에서 Host 줄이 빠지면 400.

5. 공인 IP와 NAT

내 IP는 전부 사설 · 원인은 도메인 없음이 아니라 NAT 뒤 사설망

172.25.165.29    WSL eth0
  │ Windows가 주소를 바꿈 (NAT)
172.21.69.42     Windows Wi-Fi
  │ 게이트웨이가 다시 바꿈 (NAT)
공인 IP 하나     망 전체가 나눠 씀
  │ 인터넷
172.66.147.243   example.com
내 PC의 nginxexample.com 서버
listen하는 IP사설 IP만공인 IP
연결할 수 있는 쪽내 PC, Windows, Tailscale 기기인터넷의 누구나
밖에서 먼저 연결NAT가 버림 (기록에 없는 연결)바로 도착
도메인/etc/hosts 이름만DNS에 등록

게이트웨이 = 172.21.68.1 (공유기 또는 학교망). 사설 범위 = 10.x · 172.16 ~ 172.31 · 192.168.x → 172.25와 172.21은 사설, 172.66은 공인. 100.64 ~ 100.127 = Tailscale이 쓰는 공유 범위.

6. NAT와 프록시

NAT = 패킷 겉봉의 주소만 바꿈 · 프록시 = 요청을 받아 읽고, 새 연결로 다시 보냄

NAT (공유기)프록시
TCP 연결1개 (내 PC부터 서버까지)2개 (클라이언트와 프록시, 프록시와 서버)
보는 것IP와 포트HTTP 요청 줄과 헤더
클라이언트가 아는지모름앎, 프록시 주소로 연결
계층네트워크·전송 (커널, 장비)애플리케이션 (사용자 프로그램)

T6에서 만들 proxy = 오른쪽 열. accept → read → connect → write.

조회에 쓴 명령 
# 인터페이스와 IP
ip -br addr
# 이름 → IP 명부
cat /etc/hosts
grep nameserver /etc/resolv.conf
getent ahosts example.com
# 누가 80에서 listen하나, 설정의 server_name
ss -tlnH '( sport = :80 )'
grep -E 'listen|server_name' /etc/nginx/sites-enabled/default
# 다른 IP, 다른 Host로 같은 nginx에
curl -s -o /dev/null -w '%{remote_ip} %{http_code}\n' http://172.25.165.29/
curl -s -o /dev/null -w '%{remote_ip} %{http_code}\n' -H 'Host: blog.test' http://127.0.0.1/
# Windows 쪽 주소와 게이트웨이
