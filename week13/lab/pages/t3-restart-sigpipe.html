서버 재시작과 응답 도중 떠난 client

C로 만든 작은 서버로 겪은 문제 둘 · 끈 서버가 바로 다시 안 켜짐, client 하나가 떠나자 서버가 통째로 죽음

문제요약
서버를 끄고 바로 다시 켜면 (07)Before서버를 끄면 old connection이 커널에 남아 8080을 쥐고 있어서, 바로 다시 켠 서버의 bind가 실패한다.Afterbind 앞에서 SO_REUSEADDR를 켜면, old connection은 그대로 둔 채 새 서버가 8080을 잡는다.
client가 응답 도중에 떠나면 (08)Beforeclient가 떠난 뒤에도 서버의 첫 write는 성공하지만, 두 번째 write에서 커널이 보낸 SIGPIPE가 서버를 죽인다.Aftersignal(SIGPIPE, SIG_IGN)으로 이 signal을 끄고 write의 실패를 검사하면, 그 client만 닫고 서버는 다음 client를 받는다.

1. 앞 이야기와 용어

출발점 = 06의 echo 서버 · 받은 바이트를 그대로 돌려주는 C 프로그램

06 서버는 socket → bind → listen → accept → read/write → close를 반복함. 이 페이지는 그 코드를 복사해 문제 하나씩 고친 두 프로그램(07, 08)의 기록. 07과 08은 lab에서 만든 순서대로 붙인 번호이고, 둘을 묶어 세 번째 트랙(T3)이라 부름. 서버와 client는 모두 한 PC 안(localhost)에서 실행.

용어뜻
client서버에 연결한 클라이언트 · 여기서는 터미널의 nc localhost 8080 (nc = 연결해서 친 글자를 보내고 받은 글자를 보여 주는 명령)
bind소켓에 포트 번호(8080)를 붙이는 시스템콜 · 이미 쓰이는 포트면 Address already in use로 실패
ss -tan커널이 가진 TCP 연결을 한 줄에 하나씩 보여 주는 명령 · 열 = 상태, Recv-Q, Send-Q, 내 주소:포트, 상대 주소:포트 · 이 페이지에서 "줄" = 이 출력의 한 행 · LISTEN 줄의 Recv-Q = Accept Queue에서 기다리는 연결 수, Send-Q = Accept Queue 길이 상한 · 0.0.0.0:8080 = 이 PC의 모든 주소로 오는 8080, * = 아직 상대 없음
Accept Queue커널이 연결을 맺어 놓고 서버 프로그램이 accept로 꺼내 가기를 기다리는 줄 · 프로그램이 한 client에 묶여 있으면 다음 client는 여기서 기다림 (T2)
FIN앱이 close하거나 죽으면 커널이 상대 커널에 보내는 packet · 상대 앱에게는 read가 0을 돌려주는 것으로 보임
RST받아 줄 앱이 없는 연결로 데이터가 오면 커널이 돌려보내는 packet · 그 연결을 즉시 없앰 · 아무도 듣지 않는 포트에 연결할 때도 같은 packet이 와서 즉시 실패
old connection한쪽 앱이 끝났는데도 커널에 아직 남은 연결 · 상태 이름은 아래 셋 중 하나 · 서버 쪽 줄이 남아 있으면 그 줄이 8080을 쥠
· TIME-WAIT양쪽이 FIN을 주고받은 뒤, 먼저 끝낸 쪽 커널이 약 60초 남겨 두는 상태 · 늦게 온 옛 바이트를 버리고, 상대가 FIN을 다시 보내면 다시 답하려고
· FIN-WAIT-2내 FIN은 보냈고 상대의 FIN을 기다리는 상태
· CLOSE-WAIT상대의 FIN은 받았고 내 앱이 아직 close하지 않은 상태
SO_REUSEADDR소켓 옵션 · old connection이 포트를 쥐고 있어도 새 소켓의 bind를 허락 · setsockopt로 켬
SIGPIPE끊긴 연결에 write한 프로세스에 커널이 보내는 signal · 기본 동작은 프로세스 종료 · signal로 죽은 프로세스의 exit code = 128 + signal 번호 13 = 141

2. 서버를 끄고 바로 다시 켜면 (07)

old connection이 포트를 쥐고 있음 → bind 앞에서 SO_REUSEADDR를 켜서 비켜 감

상황
06 서버를 client가 붙은 채 Ctrl-C로 끄고 바로 다시 실행 → bind: Address already in use · 1분쯤 기다리면 켜짐
원인
서버가 죽으면서 커널이 client에게 FIN을 보냄 → 서버 쪽 커널에 old connection이 남아 8080을 쥠 · 06에서는 client nc도 곧 닫혀 TIME-WAIT, 07에서는 nc를 열어 둬서 FIN-WAIT-2 · 이름만 다르고 둘 다 포트를 쥔 old connection
질문
고치고 다시 켜는 일이 잦은 웹 서버가 매번 1분을 기다려야 하나
내 예측
① 옵션을 켜면 바로 켜도 bind 성공② 새 서버가 old connection을 이어받음
int reuse = 1;            // socket() 다음, bind() 앞
if (setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof(reuse)) < 0) {
    perror("setsockopt");  // SOL_SOCKET = 이 옵션이 소켓 수준의 옵션이라는 표시
    exit(EXIT_FAILURE);
}

다시 켠 직후의 ss -tan:

LISTEN      0  8   0.0.0.0:8080      0.0.0.0:*          # 다시 켠 서버, client를 기다리는 소켓
FIN-WAIT-2  0  0   127.0.0.1:8080    127.0.0.1:53358    # old connection의 서버 쪽, 주인 프로세스는 이미 없음
CLOSE-WAIT  0  0   127.0.0.1:53358   127.0.0.1:8080     # old connection의 client 쪽, nc가 아직 열려 있음
실제
① 맞음② 틀림: old connection은 새 서버와 별개의 줄로 남았다가 사라짐 · 새 client는 다른 포트(44540, 이전 client는 53358)로 새 연결
이유
옵션은 bind의 판정만 바꿈, old connection은 건드리지 않음 · 새 client는 포트가 달라 old connection과 섞일 일이 없음 · 서버와 client가 한 PC라 한 연결의 두 끝이 한 목록에 같이 보임
과제
setsockopt를 bind 뒤로 옮김 → 다시 bind: Address already in use · bind는 불리는 순간 옵션을 보고 판정, 그 뒤에 켠 옵션은 늦음
웹 서버에서
listen 소켓을 여는 함수에 위 덩어리를 bind 앞에 그대로
전체 코드
07-reuseaddr/reuse_server.c

3. client가 응답 도중에 떠나면 (08)

떠난 client에게 쓰면 커널이 SIGPIPE로 서버를 죽임 → signal을 끄고, write의 실패를 보고 그 client만 닫음

상황
07 코드를 복사해 1초마다 tick N을 20번 보내는 서버로 바꿈 = 긴 응답을 보내는 웹 서버 · 서버는 보낼 때마다 자기 화면에 wrote tick N, client를 받으면 accepted, client를 닫으면 closed를 찍음 · client가 tick 3을 받고 Ctrl-C
질문
응답 도중 client가 브라우저를 닫으면 서버는
내 예측
① 떠난 뒤 첫 write는 성공, 다음에서 오류② client 쪽 커널에 TIME-WAIT③ client 쪽 커널이 "더 보내지 마" 신호를 줌
실제
서버가 wrote tick 4까지 찍고 종료, closed 없음, exit code 141① 시점은 맞음, 오류 대신 프로세스 종료② 틀림: 양쪽 어디에도 줄 없음③ 맞음: RST · 서버 프로세스가 사라져 다음 client는 연결 즉시 실패

순서대로:

client Ctrl-C       → client 커널이 FIN을 보냄     # "더 안 보낸다"는 뜻일 뿐, "안 받는다"가 아님
서버 write(tick 4) → 성공                       # 성공 = 내 커널의 Send Buffer에 넣었다는 뜻
                   → tick 4가 client 커널에 도착   # 받을 앱이 없음 → 버려짐
                   → client 커널이 RST       # 이 연결은 없다, 연결이 바로 사라짐 → TIME-WAIT도 없음
서버 write(tick 5) → 서버 커널이 SIGPIPE        # 앱은 이 순간에야 앎 → 기본 동작으로 종료 (141)

고친 코드 (tick을 보내는 함수 tick(conn_fd) 안, main이 client마다 이 함수를 부른 뒤 close):

signal(SIGPIPE, SIG_IGN);                 // main 첫 줄 · SIG_IGN = 이 signal을 무시하라는 값

if (write(conn_fd, buffer, length) < 0) {  // signal 대신 -1이 돌아옴
    perror("write");                      // 실패 이유를 찍음 → "write: Broken pipe"
    return;                               // 이 client만 끝 → main이 close → 다음 accept
}
고친 뒤
write: Broken pipe → closed → 다음 client accepted, 정상으로 tick을 받음
두 줄 중결과 · 이유
둘 다 없음서버 종료 (141) · SIGPIPE의 기본 동작
write 검사만 (과제)서버 종료 (141), perror까지 못 감 · signal이 write가 돌아오기 전에 프로세스를 끝냄
signal 줄만 (추가 실험)서버는 살지만 떠난 client에게 tick 5부터 20까지 계속 써서 매번 -1 · 그동안 다음 client는 Accept Queue에서 아무것도 못 받음 · 실패를 보고 멈추는 코드가 없음
둘 다그 client만 닫고 다음 client로
웹 서버에서
main 첫 줄에 signal 한 줄 · 응답을 쓰는 모든 write에 검사
전체 코드
08-sigpipe/tick_server.c
