# L1: 그는 Connection Verdict가 IP, JA4, Block table만 보고 drop은 RST로 끝난다고 말한다. drop이 아끼는 비용과 CIDR 표기는 아직이다

L1 퀴즈 5/6. 맞은 것: handshake 전 신호, 403이 안 되는 이유(HTTP가 없음), drop의 RST, cache miss, 라운드 4의 IP 회전.

**틀린 것 (오해 교정 대상):**
- 퀴즈 3: drop이 403보다 아끼는 비용으로 "Origin까지의 왕복"을 골랐다. 403도 Origin에 가지 않는다. 차이는 TLS handshake의 RSA 서명(요청 하나 CPU 2.1 ms 중 0.9 ms)이다. 비용을 "어느 단계까지 갔나"로 세는 습관을 L4(비용 비대칭)에서 다시 확인한다.
- 예측 1: `spread`의 `000`을 4160으로 예측했다. `127.0.0.16/28`을 ".16부터 .28까지"로 읽었다. `/28`은 앞 28 bit가 고정이라는 뜻이고, 남는 4 bit가 주소 16개(.16 ~ .31)다. 정답 5120. CIDR 표기는 언어나 도구 사실이므로 직접 설명했다.

**맞은 판단:** 4절 과제에서 JA4 label tarpit 규칙을 맨 아래에 두었다. 이유는 "tarpit은 붙잡는 동안 비용이 드니까 drop이 먼저"였다. 첫 매치가 이기는 규칙 표에서 순서가 곧 비용 판단이라는 점을 잡았다. L5의 `verdict_decide` 규칙 순서에서 이 판단을 다시 쓴다.

**세션에서 물은 것:** handshake 전에는 무엇을 할 수 있나, Block list와 Block table의 차이(고정 범위 대 시간 제한 키, JA4 키, 한도와 밀어내기), JA4는 개인 고유값인가(아니다, 라이브러리 지문이다). 그는 "Connection Verdict는 결국 블랙리스트 확인"으로 요약했고, 우리 코드에서는 맞다. JA4의 모양은 L2의 `ja4_format`을 치면서 익히기로 했다.
