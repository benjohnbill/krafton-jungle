2. 우리 bucket의 숫자

노트의 token bucket이 우리 코드에서는 숫자 다섯 개다.

이름어디뜻
ratestruct rate_limit_options1초마다 돌아오는 token 수 (--rate)
burststruct rate_limit_optionskey 하나가 가질 수 있는 token의 최대 (--burst). 새 key는 가득 찬 채로 시작한다
key_maxstruct rate_limit_options표에 둘 key 수. 차면 가장 오래 안 쓴 key를 잊는다
tokensstruct bucket그 key에 지금 남은 token. 소수일 수 있다
laststruct bucket그 key가 마지막으로 take한 시각 (초)

key는 기본이 client IP다 (--rate-key ip). rate_limit_take는 통과면 0을, 거절이면 다음 token까지의 초(최소 1)를 돌려준다. 이 값이 429의 Retry-After가 된다. 아래는 burst 3, rate 1일 때 key 하나의 시간 그림이다 (tests/test_rate_limit.c의 첫 테스트와 같은 숫자).

시각(초)  요청   take 전 tokens          돌려주는 값   take 뒤 tokens
0.0       1번    3 (새 key, 가득)        0  통과       2
0.0       2번    2                       0  통과       1
0.0       3번    1                       0  통과       0
0.0       4번    0                       1  거절 (429)  0
1.0       5번    0 + (1.0 - 0.0) × 1 = 1  0  통과       0

5번 줄을 본다. token을 채우는 timer는 따로 없다. take가 불릴 때 (now - last) × rate를 한 번에 더한다.
