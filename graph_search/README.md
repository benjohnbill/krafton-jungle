# graph_search — BFS를 눈으로 확인하기

그래프 탐색 코드를 "읽어서" 이해하는 대신, **매 바퀴마다 모든 변수의 상태를
찍어 보고**, **일부러 망가뜨려서 무엇이 깨지는지 대조하는** 방식의 학습 자료입니다.

## 예제 그래프 (`graph.py`)

```
    A ────── B ────── C
    │        │        │
    D ────── E ────── F
             │
             G
```

간선은 모두 양방향입니다. 사이클이 두 개(`A-B-E-D-A`, `B-C-F-E-B`) 있는데,
이 사이클 때문에 `visited`가 필요해집니다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `graph.py` | 위 그래프의 인접 리스트 정의 |
| `bfs_trace.py` | 정상 BFS. 매 바퀴 `visited`와 `q`의 내용과 크기를 출력 |
| `bfs_no_visited.py` | `visited`를 없앤 BFS. 무한 루프에 빠지는 모습 |

## 실행

```bash
python3 bfs_trace.py        # 'A'에서 출발
python3 bfs_trace.py G      # 'G'에서 출발
python3 bfs_no_visited.py
```

## 무엇을 보아야 하는가

### 1. 루프는 두 겹이다

```python
while q:                   # 바깥: '노드 하나를 처리'를 반복 -> 노드 개수만큼 돎
    v = q.popleft()        #       그러므로 이 줄도 노드 개수만큼 실행됨
    for w in graph[v]:     # 안쪽: 'v의 이웃을 살펴봄'을 반복 -> v의 이웃 수만큼
        ...
```

`popleft()`는 프로그램 전체에서 한 번 실행되는 것이 아니라 **바깥 루프가 돌 때마다**
실행됩니다. 코드를 위에서 아래로 한 번만 읽으면 이 구조가 안 보입니다.

### 2. `w`는 `for`문이 만드는 변수다

`for w in graph[v]:`라는 줄 자체가 `w`의 정의입니다. `graph[v]`가 `['B', 'D']`라면
파이썬이 `w = 'B'`로 한 바퀴, `w = 'D'`로 한 바퀴 돌립니다. 미리 선언할 필요가 없습니다.

### 3. `visited`와 `q`는 역할이 다르다

같은 값을 받지만 살아가는 방식이 정반대입니다.

| | `visited` | `q` |
|---|---|---|
| 값이 나가는가 | **절대 안 나감** | 처리하면 나감 |
| 크기 변화 | 늘기만 함 (계단) | 늘었다 줄었다 (산) |
| 끝났을 때 | 노드 전부 | **텅 빔** |
| 대답하는 질문 | "얘 본 적 있어?" | "다음에 누구 할래?" |

`visited`는 여권의 입국 도장이고, `q`는 오늘 할 일 목록입니다.
`bfs_trace.py`의 출력에서 두 크기의 변화를 나란히 보면 이 차이가 바로 드러납니다.

`bfs_no_visited.py`는 `visited`를 지웠을 때 무슨 일이 일어나는지 보여줍니다.
`q`가 한 번도 줄지 않고 계속 커지므로 `while q:`가 영원히 끝나지 않습니다.
**`visited`는 값을 담는 통이 아니라, 같은 일을 두 번 하지 않게 막는 안전장치입니다.**
