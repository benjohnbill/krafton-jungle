close와 실패: 끊는 쪽, 남는 쪽, 죽는 쪽

레슨 L3 · T3 바로 앞 · 약 8분 · 목표: 연결이 끝나거나 실패할 때 각 칸에 무엇이 남고 앱이 무엇을 받는지 말하기

0. L2 복습

답을 먼저 말하고 연다. 앱이 read하기 전 바이트는 어느 칸에 있고, ss의 어느 열에 보이나?

답 열기

서버 커널, 그 연결 소켓의 수신 버퍼에 있다. ESTAB 줄의 Recv-Q가 그 바이트 수다. 06-echo에서 B의 hello 두 번이 Recv-Q 12로 보였다.

1. 상대가 끊으면 read는 0을 돌려준다

한 문장. 한쪽 앱이 close하면 그 커널이 상대 커널에 "끝"을 알린다. 상대 앱의 read는 버퍼에 남은 바이트를 다 꺼낸 뒤 0을 돌려준다. 0이 "손님이 떠났다"는 뜻이다.
close() (06에서 A를 Ctrl-C) "끝" 알림 read() → 0. 서버 앱이 비로소 앎

06-echo의 while ((length = read(...)) > 0)가 이 0에서 끝났고, 그래서 closed가 찍혔다. read(2): "zero indicates end of file" (read(2)). 웹서버는 이 0을 보고 그 손님의 연결을 닫는다.

2. 먼저 끊은 쪽에 TIME-WAIT이 남는다

06에서 직접 봤다. A를 끊었을 때는 클라 쪽(40270)에, 서버를 먼저 끈 뒤에는 서버 쪽(127.0.0.1:8080)에 TIME-WAIT 한 줄이 남았다. 먼저 close한 쪽의 커널이 연결 하나를 약 60초 더 붙들고 있는 상태다. 앱은 이미 close했으니 fd도 없다.

3. 그 TIME-WAIT이 서버의 재시작을 막는다

서버 쪽 TIME-WAIT 줄은 포트 8080을 쥐고 있다. 그래서 바로 다시 켠 서버의 bind가 Address already in use로 실패했다. 웹서버는 고치고 다시 켜는 일이 잦으니 매번 1분을 기다릴 수 없다. 해결책은 소켓 옵션 SO_REUSEADDR이고, T3에서 직접 넣는다. 한 가지 조건이 있다. socket(7): "only with the SO_REUSEADDR option when this option was set both in the previous program ... and in the program that wants to reuse the port" (socket(7)). 이 PC에서도 새 서버만 옵션을 켜면 실패하고, 옛 서버와 새 서버 둘 다 켜야 성공했다 (2026-11-20).

4. 아무도 듣지 않는 포트는 바로 거절된다

06 과제에서 4번째 nc는 대기열이 꽉 찬 서버에 답을 못 받고 약 2분 동안 다시 보내다 조용히 끝났다. 포트에 listen 소켓이 아예 없으면 다르다. 서버 커널이 바로 거절을 돌려보내고, 클라 앱의 connect는 즉시 Connection refused로 실패한다. 이 PC에서 0.000초였다.

서버 쪽 상황서버 커널클라 앱이 겪는 일
listen 소켓 없음 (서버 꺼짐)바로 거절즉시 Connection refused
accept 대기열 꽉 참 (06 과제)답 없이 버림약 2분 멈췄다가 실패

웹서버로 치면 proxy가 꺼진 backend에 붙을 때 받는 오류가 첫 줄이다.

5. 끊긴 손님에게 write하면 서버가 죽는다

한 문장. 상대가 이미 끊은 연결에 write하면, 첫 번째는 성공한 것처럼 돌아오고 두 번째에서 커널이 서버 프로세스에 SIGPIPE를 보낸다. 기본 동작은 프로세스 종료다.

write(2): "EPIPE ... the writing process will also receive a SIGPIPE signal" (write(2)). 이 PC에서 작은 C 프로그램이 첫 write는 3을 돌려받고, 둘째 write에서 종료 코드 141(128 + SIGPIPE 13)로 죽었다. 손님이 응답 도중에 브라우저를 닫는 일은 흔하다. 손님 하나 때문에 서버 전체가 죽으면 안 되니, T3에서 이걸 막는 법을 본다. 06의 echo_server.c는 write의 반환값을 보지 않는다.

6. 직접 본다 (퀴즈를 먼저 고르고)

4절의 즉시 거절. 9999 포트에는 아무것도 듣지 않는다.

# 아무도 듣지 않는 포트. 얼마나 빨리 끝나나
time curl http://localhost:9999/

curl은 connect의 ECONNREFUSED를 자기 문장으로 바꿔 찍는다. 이 PC의 curl은 curl: (7) Failed to connect to localhost port 9999 after 3 ms: Could not connect to server였다 (2026-11-20). 출력을 세션에 붙여 넣는다. 1~3절은 06에서 이미 봤고, 5절은 T3에서 직접 만든다.
