2. 같은 식, 두 코드

영상 13:26 이후: 한 layer의 식 a⁽¹⁾ = σ(W a⁽⁰⁾ + b)를 Python 한 줄로 바꿈
우리 mnist에도 같은 일을 하는 코드가 있음

영상 (Michael Nielsen 코드)

# 영상 화면 그대로
def feedforward(self, a):
    for b, w in zip(self.biases, self.weights):
        a = sigmoid(np.dot(w, a) + b)
    return a

우리 mnist (요약)

# src/network.py, BatchNorm과 Dropout은 뺌
self.layers = [Affine(W1, b1), ReLU(),
               Affine(W2, b2)]

def forward(self, x):
    out = x
    for layer in self.layers:
        out = layer.forward(out)
    return out  # logits

# src/layers.py, Affine docstring:
# 수식은 y = x @ W + b 입니다.

3. 문제 1: neuron 하나의 weight는 W1의 어디에?

영상 8:39: 두 번째 layer의 neuron 하나에 연결선 784개
그 weight 784개를 28×28 격자 그림으로 보여 줌

그 격자 그림 한 장은 우리 W1의 어디일까? 그리고 영상은 np.dot(w, a), 우리는 x @ W: 곱하는 순서는 왜 반대일까?

실행하기 전에 A부터 F까지 출력을 예측. mnist/src에서 python을 켜고 붙여 넣음

import numpy as np
from network import TwoLayerNet

W1 = TwoLayerNet().params["W1"]
print("A", W1.shape)
print("B", W1[0].shape, W1[:, 0].shape)
print("C", W1[:, 0].reshape(28, 28).shape)

x = np.random.default_rng(1).random((4, 784))  # batch: 이미지 4장
print("D", (x @ W1).shape)
print("E", np.allclose(W1.T @ x[0], (x @ W1)[0]))
W1 @ x[0]  # F: 영상 순서 그대로 곱하면?
  • B: 둘 중 neuron 하나의 weight 784개는 어느 쪽?
  • E: True와 False 중 어느 쪽?
  • F: 에러가 난다면 왜?
실행 결과와 해설 
A (784, 128)
B (128,) (784,)
C (28, 28)
D (4, 128)
E True
ValueError: matmul: Input operand 1 has a mismatch in its core dimension 0, ...
(size 784 is different from 128)

영상의 W와 우리 W1

  • 영상 W는 (16, 784): 행 하나 = neuron 하나. 입력 a는 이미지 1장을 세운 (784,), 결과 np.dot(w, a)는 (16,)
  • 우리 W1은 (784, 128): 열 하나 = neuron 하나 (A)
  • 그래서 영상의 격자 그림 = W1[:, 0].reshape(28, 28) (B의 두 번째, C)
  • W1[0]은 (128,): 픽셀 0번 하나가 neuron 128개 각각에 주는 weight

순서가 반대인 이유

  • 우리 x는 (N, 784): 행 하나 = 이미지 1장. batch를 한 번에 계산하려고 이미지를 행으로 쌓음
  • x @ W1 = (N, 784) @ (784, 128) → (N, 128) (D)
  • 이미지 1장만 떼어 영상 방향으로 쓰면 W1.T @ x[0], 값이 같음 (E). 우리 W1 = 영상 W의 전치
  • W1 @ x[0]은 안쪽 차원이 128과 784로 달라서 에러 (F). 곱하는 순서는 shape이 정함

정리: 식은 같음. 차이는 이미지 N장을 행으로 쌓은 것 하나

4. 문제 2: 마지막 layer, sigmoid 없이도 답을 고를까?

영상 10:15: 모든 layer에 sigmoid, activation은 전부 0~1 사이
영상 16:50: 요즘은 sigmoid 대신 ReLU

우리 mnist는 다름. hidden layer에는 ReLU, 마지막 Affine 뒤에는 activation function 없음. forward docstring: (batch_size, 10) logits. 확률이 아니라 점수입니다.

sigmoid로 0~1에 눌러 주지 않아도, 영상의 "가장 밝은 neuron이 답"은 그대로 통할까?

아래 코드는 어디서든 실행됨. logits는 이미지 1장에 대해 지어낸 값

import numpy as np

logits = np.array([1.3, -0.4, 2.7, 0.2, -1.8, 0.9, 3.4, -0.6, 2.1, 0.0])
sigmoid = 1 / (1 + np.exp(-logits))
print("A", logits.argmax(), sigmoid.argmax())
print("B", sigmoid.round(2))
print("C", sigmoid.sum().round(2))
  • A: 두 숫자는 같을까?
  • C: sigmoid 10개의 합은 1일까?
실행 결과와 해설 
A 6 6
B [0.79 0.4  0.94 0.55 0.14 0.71 0.97 0.35 0.89 0.5 ]
C 6.24

답 고르기에는 순서만 필요

  • sigmoid는 큰 값을 더 큰 값으로 보내는 함수(단조 증가) → 순서가 그대로 → argmax도 같음 (A)
  • softmax도 마찬가지. network.py의 predict docstring에 같은 설명 있음
  • 그래서 logits가 음수거나 1보다 커도 가장 큰 값이 답

0~1 사이라고 확률은 아님

  • sigmoid 값은 하나하나 0~1 사이 (B), 그러나 합은 6.24 (C)
  • neuron 10개가 각자 따로 매긴 점수일 뿐, 확률 분포가 아님
  • 합이 1인 확률은 softmax가 만듦. 우리 코드에서는 SoftmaxWithLoss가 맡음

hidden layer의 ReLU

  • ReLU = max(0, x): 0 이상, 위로는 한계 없음
  • 영상의 "neuron = 0~1 사이 숫자를 담는 칸"은 우리 hidden layer에서는 성립하지 않음
  • 영상 p.s.의 이유: ReLU가 학습이 훨씬 쉬움
