CLI 명령어를 통한 학습

13주차 첫날, 책을 읽기 전에 CLI 도구로 직접 관찰 · DNS부터 시스템콜까지 다섯 프로브

1. 이렇게 시작한 이유

읽고 나서 만들기 대신 겪고 나서 만들기 → 관찰에서 생긴 질문을 팀 프로토타입으로

웹 서버 주차의 출발점을 책 대신 명령으로 정함. curl, telnet, nc, strace로 요청 하나를 직접 따라가고, 다음 트랙부터는 작은 C 코드를 손으로 따라 침. 각 프로브의 끝은 힌트 없이 혼자 하는 변경 과제 하나.

트랙겪어 볼 것상태
T1 CLI이름 → IP, HTTP의 모양, socket → bind → listen → accept이 페이지
T2 socket Cecho 서버 따라치기, 두 번째 클라이언트가 멈추는 이유다음
T3 TCPSO_REUSEADDR, TIME_WAIT, handshake, SIGPIPE
T4 HTTP정적 GET, MIME, 404, keep-alive, 깨진 요청
T5 concurrencyfork, pthread, epoll을 wrk로 비교
T6 proxyReverse Proxy, 중계, C Forward Proxy

2. 요청 하나의 흐름

다섯 단계 · 단계마다 본 프로브와 출력의 자리가 다름

오가는 것누가 → 누구에게본 곳
1IP 주소는? → IP 목록curl과 DNS 서버01 · curl의 * 줄
2TCP 연결내 커널과 서버 커널05 · connect, accept
3GET / HTTP/1.1, 헤더, 빈 줄curl → 서버 프로그램02 03 · > 줄
4HTTP/1.1 200 OK, 헤더, 빈 줄서버 프로그램 → curl02 03 · < 줄
5body (HTML)서버 프로그램 → curl04 · 브라우저가 받는 대로 그림

웹 서버를 만든다 = 3을 읽고 4와 5를 쓰는 일 · 1은 클라이언트, 2는 커널이 처리 (서버는 listen과 accept로 준비만).

3. 프로브 다섯

명령 · 하는 일 · 본 것

01DNS: 이름 → IP

ip -br addr                    # 내 PC의 인터페이스와 IP
getent ahosts example.com      # /etc/hosts 다음 DNS까지, OS 방식으로
dig A example.com +short       # DNS 서버에 직접: IPv4
dig AAAA example.com +short    # IPv6
cat /etc/hosts /etc/resolv.conf
하는 일
이름이 IP로 바뀌는 곳 확인. /etc/hosts가 먼저, 없으면 resolv.conf의 DNS 서버
본 것
example.com 하나 → IP 넷 · localhost는 DNS 없이 /etc/hosts에서 · 포트는 DNS가 아니라 URL이 정함
더 보기
내 PC의 주소 지도 · 인터페이스, 이름, Host, NAT

02curl: HTTP의 모양

curl -sv http://example.com/ -o /dev/null 2>&1 | bat -l http
curl -sv http://example.com/nothing -o /dev/null 2>&1 | bat -l http
curl -sv http://localhost/ -o /dev/null 2>&1 | bat -l http
하는 일
-v = 연결 과정과 헤더를 stderr로 · -o /dev/null = body 버림 · 2>&1 = 둘을 합쳐 bat으로
본 것
* curl의 기록 · > 보낸 것 · < 받은 것 · { 받은 body 크기. 내 쪽 포트는 실행마다 바뀜(커널이 고른 임시 포트) · /nothing = 연결은 같고 상태 줄만 404 → 판단은 서버 프로그램

03telnet: HTTP를 손으로

telnet localhost 80
# 연결되면 직접 치고 Enter 두 번
GET / HTTP/1.1
Host: localhost

nc localhost 80                # 줄 끝 \n만 (nc -C면 \r\n)
하는 일
curl이 대신 쳐 주던 요청 텍스트를 직접 입력. telnet은 HTTP를 모름 → 바이트를 그대로 보여 줌
본 것
빈 줄 전까지 서버는 다음 헤더를 기다림 = 요청의 끝은 빈 줄 · 1.0은 응답 후 연결 닫힘, 1.1은 유지(keep-alive)
바꾼 요청응답 · 연결판단 시점
요청 줄 앞 공백, HTTP1.1400 · close요청 줄을 읽자마자 (문법)
HTTP/1.1에서 Host 없음400 · close헤더를 다 읽은 뒤
메서드 GOT405 · keep-alive문법 통과 후 (의미)
줄 끝 \n만200 · keep-alive받아 줌: 읽을 때 너그럽게, 쓸 때 엄격하게

04nc: 내가 서버

nc -l 8080
# Windows 브라우저에서 http://localhost:8080/hello → 요청이 찍히면 직접 응답
HTTP/1.0 200 OK
Content-Type: text/html

<h1>hello from nc</h1>
하는 일
역할 바꾸기: 브라우저가 클라이언트, 내가 서버
본 것
브라우저 요청 = curl보다 헤더가 훨씬 많음(언어, 압축, prefetch) · 친 줄마다 바로 렌더링 · Content-Length 없으면 연결이 끊길 때까지 로딩 · Content-Length: 5면 5바이트만 → <h1>H만 그림 · 경로는 nc가 안 읽음 → 어느 경로든 같은 화면 · nc -l은 한 번만 받음 → 새로고침 = 연결 거부

05strace: 서버가 커널에 부탁하는 순서

strace -f -e trace=network nc -l 8080        # 터미널 1
nc localhost 8080                            # 터미널 2
ss -tanp 'sport = :8080'                     # 터미널 3
strace -f -e trace=network curl -s http://example.com/ -o /dev/null
하는 일
프로그램이 커널에 들어간 네트워크 시스템콜만 순서대로 보기
본 것
socket → bind → listen 다음 accept4에서 멈춤 · listen 소켓 fd 3, 연결 소켓 fd 4 · curl은 DNS(:53) → connect(:80) → 요청 텍스트 sendto
