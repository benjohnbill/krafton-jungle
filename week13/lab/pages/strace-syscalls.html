Server to Kernel 요약

nc -l 8080을 strace로 본 서버 쪽 시스템콜 · 같은 연결을 fd 표, ss, curl의 클라이언트 쪽까지

1. 서버: socket부터 accept까지

socket → bind → listen 다음 accept4에서 멈춤 → 클라이언트 접속 순간 fd 4 반환

$ strace -f -e trace=network nc -l 8080
socket(AF_INET, SOCK_STREAM, IPPROTO_TCP) = 3          # TCP 소켓 생성 → fd 3
setsockopt(3, SOL_SOCKET, SO_REUSEADDR, [1], 4) = 0  # 옵션 (nc가 붙인 것)
setsockopt(3, SOL_SOCKET, SO_REUSEPORT, [1], 4) = 0
bind(3, {sin_port=htons(8080), sin_addr=inet_addr("0.0.0.0")}, 16) = 0   # 포트 8080, 모든 IPv4 주소
listen(3, 1) = 0                                      # 받겠다는 선언, 대기열 1 → ss에 LISTEN 등장
accept4(3, {sin_port=htons(48196), sin_addr=inet_addr("127.0.0.1")}, [128 => 16], SOCK_NONBLOCK) = 4   # 여기서 잠듦 → 접속이 오자 깨어나 fd 4
호출반환뜻
socket3소켓 생성. 0·1·2는 터미널이 차지 → 첫 소켓이 3
bind0포트 정하기. 0 = 성공, 실패면 -1과 errno
listen0이 소켓으로 연결을 받겠다는 선언. 이후 연결은 커널이 대기열에 쌓음
accept44대기열에서 연결 하나 꺼내기. 없으면 잠듦. 꺼낸 연결 = 새 소켓, 새 fd

2. fd가 두 개인 이유

listen 소켓 3은 새 연결 요청만 받음 · accept가 손님마다 새 소켓 → 3은 다음 손님을 위해 남음

서버 nc

$ ls -l /proc/758619/fd
0 -> /dev/pts/11
1 -> /dev/pts/11
2 -> /dev/pts/11
3 -> socket:[4514524]   # listen
4 -> socket:[4514525]   # 연결

클라이언트 nc

$ ls -l /proc/$(pgrep -n nc)/fd
0 -> /dev/pts/4
1 -> /dev/pts/4
2 -> /dev/pts/4
3 -> socket:[4519083]   # connect한 소켓 하나

대괄호 숫자 = 커널이 소켓마다 붙인 번호(inode). 서버 3과 4가 다름 → accept가 새 소켓을 만든 증거. 서버 4와 클라이언트 3도 다름 → 한 연결의 양 끝을 각자 따로 쥠. fd 번호는 프로세스마다 따로라서 양쪽 모두 3부터 시작.

3. 같은 포트 8080에 소켓 둘

연결 소켓도 포트 8080 그대로 · 커널은 주소 네 개(내 IP·포트, 상대 IP·포트)로 구분

$ ss -tanp 'sport = :8080'
State   Local Address:Port   Peer Address:Port   Process
LISTEN  0.0.0.0:8080         0.0.0.0:*           users:(("nc",pid=758619,fd=3))
ESTAB   127.0.0.1:8080       127.0.0.1:48196     users:(("nc",pid=758619,fd=4))

LISTEN 줄 = 상대가 *, 아무나. ESTAB 줄 = 상대가 48196번 포트의 클라이언트 하나. 손님이 하나 더 오면 상대 포트만 다른 ESTAB 줄과 fd 5 추가.

4. 클라이언트: curl의 순서

DNS 질문(:53) → TCP connect(:80) → 요청 텍스트 sendto → 응답 recvfrom

$ strace -f -e trace=network curl -s http://example.com/ -o /dev/null
# nscd(이름 캐시)에 먼저 물어봄 → 없음(ENOENT) → 다음 방법으로
connect(3, {sa_family=AF_UNIX, sun_path="/var/run/nscd/socket"}) = -1 ENOENT
strace: Process 781016 attached   # DNS 조회용 스레드 → -f가 없으면 아래가 안 보임
connect(5, {sin_port=htons(53), sin_addr=inet_addr("100.100.100.100")}) = 0   # DNS 서버(UDP)
sendmmsg(5, "...\7example\3com..." x2)   # A와 AAAA 질문을 함께
recvfrom(5, "...example.com..." , {sin_port=htons(53)})   # 답 두 개
# UDP connect로 각 주소의 경로만 확인 (패킷은 안 나감) → 시도 순서 정렬
connect(5, {sin_port=htons(80), sin_addr=inet_addr("104.20.23.154")}) = -1 EINPROGRESS   # 진짜 TCP 연결
sendto(5, "GET / HTTP/1.1\r\nHost: example.co"..., 75) = 75   # 요청 텍스트, 줄 끝 \r\n
recvfrom(5, "HTTP/1.1 200 OK\r\nDate: ..."..., 102400) = 936   # 응답 텍스트

EINPROGRESS = 실패가 아님. 소켓이 non-blocking이라 연결이 끝나기 전에 바로 돌아온 것. sendto의 75바이트가 02의 > 줄, recvfrom의 936바이트가 < 줄과 body.

5. 서버와 클라이언트

서버 (nc -l)클라이언트 (curl)
준비socket → bind → listenDNS 조회 → socket
연결accept에서 기다림 → 새 fdconnect로 먼저 두드림
소켓 수listen 1 + 연결마다 1연결 1
대화연결 fd로 read · write같은 fd로 sendto · recvfrom
다시 돌려 보기 
# 터미널 1: 서버
strace -f -e trace=network nc -l 8080
# 터미널 2: 접속 후 아무 글자나
ss -tlnp | grep 8080
nc localhost 8080
# 터미널 3: 연결된 상태에서 fd 표와 소켓
ls -l /proc/$(pgrep -o nc)/fd
ss -tanp 'sport = :8080'
# 클라이언트 쪽
strace -f -e trace=network curl -s http://example.com/ -o /dev/null 2>&1 | bat -l log
