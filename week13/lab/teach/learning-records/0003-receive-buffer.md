# L2: 그는 read 전까지 바이트가 서버 커널의 수신 버퍼에 있다고 말한다

L2 퀴즈는 3/4. 3번(`no_read.py`의 Recv-Q)에서는 0을 골랐다. 그러나 예측 1에서 "서버 커널에 들어는 왔는데, 읽지를 않았으니까 6"이라고 이유와 함께 맞게 썼다. 그래서 오답은 스스로 바로잡은 것으로 본다. lesson 범위는 그가 정했다: ACK, tcpdump, 커널 소스는 웹서버에 꼭 필요하지 않아서 뺐다 (NOTES.md).

**06-echo 예측** (06-echo README의 볼 것에 옮긴다. 실행 전에 다시 묻고, 실행 뒤 비교한다):
1. A가 연결된 동안 B가 `hello`를 치면, 서버 쪽 B 줄의 Recv-Q는 6이다. 서버 커널에 들어왔지만 아무도 읽지 않았다.
2. A가 끊으면 B는 그제야 순차적으로 `accept`된다. 그리고 다시 치지 않아도 `hello`의 echo를 받는다. 바이트가 버퍼에 남아 있기 때문이다.
3. L1에서 넘어온 예측: 첫 클라이언트가 붙어 있어도 두 번째의 `connect`는 끝나는가 (0001 참조).
