핵심가져온 곳, 이유
왜 지금User-Agent와 TLS를 둘 다 Chrome으로 맞춘 crawler도 요청의 양은 숨기지 못한다L2 확인 질문의 답. ②가 못 잡는 crawler가 ④로 온다
보는 것key(기본은 client IP)마다 요청 수. 요청마다 token 하나를 쓰고, token은 일정한 속도로 찬다노트 03 rate limit의 token bucket 그림. 8번 규칙의 "token"이 이것이다

3. 우리 코드: rate_limit_take

옆으로 밀어 보기 →

int rate_limit_take(struct rate_limit *limit, const char *key, double now)
{
    pthread_mutex_lock(&limit->lock);
    struct bucket *bucket = bucket_find(limit, key);
    if (bucket == NULL) {
        bucket = bucket_claim(limit, key, now);
    }
    bucket_refill(bucket, &limit->options, now);
    int wait = 0;
    if (bucket->tokens >= 1) {
        bucket->tokens -= 1;
    } else {
        wait = bucket_get_wait(bucket, limit->options.rate);
    }
    pthread_mutex_unlock(&limit->lock);

    return wait;
}

src/rproxy/rate_limit.c:60-77. 8번 규칙의 "token 없음"을 정하는 함수다. 돌려준 초가 429의 Retry-After가 된다.
