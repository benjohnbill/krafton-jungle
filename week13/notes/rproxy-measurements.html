rproxy 측정: 방어마다 아끼는 비용과 옮기는 비용

rate limit만 쓰면 Origin의 비용이 rproxy로 옮겨감
429를 반복해 받는 IP를 Block table에 올리면 그 비용도 사라짐
drop과 tarpit은 rproxy의 비용까지 줄임

1. 2026-11-24: 429를 반복해 받는 IP를 Block table에

항목내용
코드CJG 1170ba3. window 안에 429를 5번 받은 IP가 또 한도를 넘으면 429와 함께 Block table에 올림 (--rate-key ip일 때만)
비교none, 이전 layers (2절), 지금 layers
Scene429를 받던 넷: repeat, longtail, revalidate, solver. 나머지 여섯은 429를 받지 않아 2절 결과가 그대로 유효함
반복3회, 중앙값 primary

rproxy CPU: rate limit이 옮긴 비용이 사라짐

아낀 것
왜 rproxy CPU가 이전 layers의 1/3 ~ 1/7, none보다도 낮음어떻게 burst 10번 통과, 429 약 8번 뒤 Block table에 올라 나머지 연결은 ②에서 drop: TLS 서명 없음
늘어난 것
왜 crawler 요청 수가 1.3 ~ 2.1배어떻게 drop은 429보다도 빨리 끝나서 crawler가 더 보냄. 그래도 요청 하나가 handshake 전에 끝나서 CPU는 줄어듦
그대로인 것
왜 Origin CPU 약 0, Origin MiB는 이전 layers와 같은 수준 (repeat 8.0)어떻게 human.py는 429를 한 번도 받지 않아 Block table에 오르지 않음. p95 16 ~ 31 ms

rate limit: Origin은 아끼고, rproxy는 더 씀

아낀 것
왜 Origin MiB가 1/59 ~ 1/588, Origin CPU는 약 0어떻게 IP마다 10초에 59번만 통과(④). repeat, revalidate는 그중 55번을 cache와 304가 답함(⑤)
옮긴 것
왜 rproxy CPU가 1.3 ~ 3배어떻게 429가 빨리 오니 crawler가 2.5 ~ 4.5배 더 보냄. rproxy에 keep-alive가 없어서 요청마다 TLS 서명(0.9 ms)을 다시 함그 뒤 1절: 429를 반복해 받는 IP를 Block table에 올려 이 비용을 없앰

drop: rproxy까지 아낌

spread
왜 rproxy CPU 15.6 → 11.1 s어떻게 주소 32개 중 16개가 Block list에 걸려 ②에서 drop: TLS 서명 없음
trapped
왜 rproxy CPU 1.2 → 0.8 s어떻게 Honeypot 한 번 뒤 Block table에 올라 연결 약 5700개가 ②에서 drop

tarpit: crawler의 발을 묶음

disguised
왜 rproxy CPU 4.9 → 0.09 s, Origin MiB 312 → 0어떻게 User-Agent와 JA4가 어긋나서 tarpit(④). 연결이 붙잡히니 crawler가 새 요청을 못 보냄. Event loop의 timer라 thread는 쥐지 않음

사용자: 진짜 사용자와 착한 bot

진짜 사용자
왜 모든 Scene에서 human.py의 p95 15 ~ 27 ms, 초당 응답 2.5 ~ 3번으로 거의 그대로: 오탐 없음어떻게 사람의 IP, JA4, 행동은 어느 규칙에도 맞지 않음
착한 bot
왜 signed의 Origin MiB 0 → 16.6: 의도한 증가어떻게 서명이 확인되어 통과(④). 1952번은 cache가 답함(⑤)

3. 열린 질문

질문다룰 곳
연결을 다시 써서 TLS 서명 횟수를 줄이면 무엇이 바뀌나 (keep-alive, session resumption)Block table로 rate limit 비용은 1절에서 해결함. keep-alive는 crawler의 비용도 함께 줄이고, 모든 Scene의 기준선을 바꿈L3 HTTP ①: 양, L4 HTTP ②: 시험과 비용 비대칭
