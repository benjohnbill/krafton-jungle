웹 서버 주차의 출발점을 책 대신 명령으로 정함. curl, telnet, nc, strace로 요청 하나를 직접 따라가고, 다음 트랙부터는 작은 C 코드를 손으로 따라 침. 각 프로브의 끝은 힌트 없이 혼자 하는 변경 과제 하나.

트랙겪어 볼 것기록
T1 CLI이름 → IP, HTTP의 모양, socket → bind → listen → acceptCLI 명령어를 통한 학습
T2 socket Cecho 서버 따라치기, 두 번째 client가 멈추는 이유한 번에 한 client만 받는 echo 서버
T3 TCPSO_REUSEADDR, TIME-WAIT, SIGPIPE서버 재시작과 응답 도중 떠난 client
T4 HTTP정적 GET, MIME, 404, keep-alive, 깨진 요청다음
T5 concurrencyfork, pthread, epoll을 wrk로 비교
T6 proxyReverse Proxy, 중계, C Forward Proxy
용어뜻
client서버에 연결하는 프로그램T1에서는 curl, telnet, nc, 브라우저
DNS이름을 물으면 IP를 알려 주는 서버와 그 규칙
/etc/hosts이름과 IP를 직접 적어 둔 파일DNS보다 먼저 봄
요청 줄요청의 첫 줄: 메서드, 경로, 버전 (GET / HTTP/1.1)
상태 줄응답의 첫 줄: 버전, 상태 코드, 설명 (HTTP/1.1 200 OK)
빈 줄헤더가 끝났다는 표시
keep-alive응답 뒤에도 연결을 닫지 않고 다음 요청을 받는 방식
Content-Lengthbody가 몇 바이트인지 알리는 헤더
시스템콜프로그램이 커널에 일을 부탁하는 호출 (socket, bind, listen, accept, connect)
fd프로세스가 커널 안의 파일이나 소켓을 가리키는 번호
listen 소켓listen을 부른 소켓, 새 연결만 받음
연결 소켓accept가 client마다 새로 만든 소켓, 대화는 여기로
