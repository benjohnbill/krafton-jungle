syscall과 네 칸 한눈에 보기

reference · lesson이 끝날 때마다 줄이 늘어난다 · 지금: L3

연결 준비 (L1)

syscall부르는 칸커널이 하는 일돌려주는 것잠드는가
socket양쪽 앱소켓을 만든다새 fd아니요
bind서버 앱소켓에 IP와 포트를 붙인다0 또는 -1아니요
listen서버 앱이후 handshake를 혼자 하고, 끝난 연결을 accept 대기열에 쌓는다0 또는 -1아니요
connect클라 앱SYN을 보내고 handshake를 끝낸다0 또는 -1handshake가 끝날 때까지
accept서버 앱대기열 맨 앞 연결을 꺼내 새 소켓으로새 fd대기열이 빌 때

대화 (L2)

syscall부르는 칸커널이 하는 일돌려주는 것잠드는가
write양쪽 앱바이트를 내 송신 버퍼에 넣고 보낸다넣은 바이트 수송신 버퍼가 찰 때
read양쪽 앱내 수신 버퍼에서 바이트를 꺼내 앱 메모리로꺼낸 바이트 수, 상대가 끊으면 0수신 버퍼가 빌 때

연결된 손님의 바이트는 주소 네 개가 맞는 연결 소켓의 수신 버퍼로 간다. 앱이 read할 때까지 커널에서 기다린다.

출처: listen(2), accept(2), socket(2).

끝과 실패 (L3)

상황커널이 하는 일앱이 받는 것
상대가 close"끝"을 받아 둔다버퍼를 다 꺼낸 뒤 read → 0
내가 먼저 close그 연결을 TIME-WAIT으로 약 60초 붙든다없음 (fd는 이미 닫힘)
서버 쪽 TIME-WAIT 중 재시작포트가 쓰이는 중bind → EADDRINUSE. 옛 서버와 새 서버 둘 다 SO_REUSEADDR를 켜야 통과
listen 소켓 없는 포트에 연결서버 커널이 바로 거절connect → 즉시 ECONNREFUSED
accept 대기열 꽉 참서버 커널이 답 없이 버림, 클라 커널이 6번 다시 보냄connect가 약 2분 뒤 실패
끊긴 상대에게 write첫 번째는 받아 주고, 다음 번에 SIGPIPE기본은 프로세스 종료 (종료 코드 141)

출처: read(2), write(2), socket(7). 표의 모든 줄을 이 PC에서 확인했다 (2026-11-20).

용어

말뜻
fd프로세스가 커널 안 물건(파일, 소켓)을 가리키는 번호. 프로세스마다 0부터 따로 센다
listen 소켓listen을 부른 소켓. 새 연결만 받는다 (listen_fd)
연결 소켓accept가 손님마다 만든 소켓. 대화는 여기로 (conn_fd)
accept 대기열handshake가 끝났지만 아직 accept로 꺼내지 않은 연결의 줄
backloglisten의 둘째 인자. accept 대기열의 길이 상한
주소 네 개상대 IP, 상대 포트, 내 IP, 내 포트. 커널이 연결 소켓을 구분하는 열쇠
수신 버퍼커널이 받은 바이트를 앱이 read할 때까지 두는 곳. 소켓마다 하나
TIME-WAIT먼저 close한 쪽 커널이 끝난 연결을 잠시 붙들어 두는 상태. 그동안 그 포트를 쥐고 있다
SIGPIPE끊긴 연결에 write한 프로세스에 커널이 보내는 신호. 기본 동작은 종료
