# 그는 방어 layer 전체를 "앞 단계일수록 싸지만 신호가 적다"는 trade-off와 운영자의 요구분석으로 정리했다

L1 뒤 문답(2026-11-24)에서 그가 스스로 세운 문제 정의: crawler가 이득 없이 부하를 준다 → 요청은 단계를 지날수록 서버에 비용을 쌓는다 → 뒤 단계일수록 거를 근거(신호)는 늘지만, 거기까지 가는 데 서버가 더 많이 주고받고 더 많이 쓴다 → 그래서 가능한 한 적은 신호로 앞 단계에서 거른다. 그는 이것을 "서버 프로그램 사용자(운영자)에 대한 요구분석 그 자체"라고 불렀다.

agent가 보탠 것: 비용 비교는 두 개다. 방어 비용 < 그 방어가 아끼는 서빙 비용, 그리고 방어 비용 < crawler가 피해 가는 비용(L4). 요구에는 반대편도 있다: 진짜 사용자를 잘못 막는 비용(`human.py`), 착한 bot을 통과시키는 일(L5).

Implications: L2~L5의 각 layer를 이 축(단계, 보이는 신호, 서버 비용, 오탐 비용)에 놓고 묻는다. PR 핵심 결정 문단과 발표의 뼈대로 쓸 수 있다. 계층 지식(TCP, TLS handshake, ClientHello)은 아직 개념이 잡히는 중이다: TLS가 TCP와 HTTP 사이의 층이라는 것까지 확인했고, ClientHello와 ServerHello의 내용은 아직이다.
