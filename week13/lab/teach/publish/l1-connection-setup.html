연결 준비와 fd: accept 전에 연결은 이미 끝나 있다

사전 학습 L1, T2(06-echo) 바로 앞, 약 10분
목표: handshake를 하는 칸과 accept가 하는 일을 나눠 말하기

0. 빈 4칸 복습

칸 이름이 가려져 있다. 왼쪽부터 네 칸의 이름을 소리 내어 말하고, socket, bind, listen, accept, connect를 부르는 칸이 어디인지 말한 뒤 연다.

답 열기

왼쪽부터 client 앱, client 커널, 서버 커널, 서버 앱이다. connect는 client 앱이, 나머지 넷은 서버 앱이 부른다. 다섯 개 모두 syscall이라서, 부르는 순간 일은 같은 쪽 커널 칸으로 넘어간다.

1. T1에서 이미 본 것

Server to Kernel 요약 §1–2: socket이 fd 3을 돌려주고, accept4가 client마다 새 fd 4를 돌려줬다. /proc/<pid>/fd에서 둘 다 socket:[inode]였다.

그래서 소켓에 read와 write를 쓴다 (QUESTIONS 03의 첫 줄). socket()은 "returns a file descriptor that refers to that endpoint", 그리고 "Once connected, data may be transferred using read(2) and write(2) calls" (socket(2)). fd는 커널 안 물건을 가리키는 번호일 뿐이고, 그 물건이 디스크 파일인지 소켓인지는 커널이 안다.

2. 새 것: handshake는 커널끼리 한다

한 문장. 서버 앱이 listen을 부른 뒤로는, 서버 커널이 혼자 handshake를 끝내고 완성된 연결을 Accept Queue에 쌓는다. accept는 그 Accept Queue에서 하나를 꺼내 새 fd를 줄 뿐이다.
listen() 이후 서버 앱은 아무것도 안 해도 된다 connect(), client 앱은 여기서 잠듦 SYN SYN-ACK ACK → client의 connect() 반환, 서버 커널은 연결을 Accept Queue에 넣음 accept(), Accept Queue 맨 앞 연결을 꺼내 새 fd로

근거 두 줄:

  • listen(2) NOTES: Linux 2.2부터 backlog는 "the queue length for completely established sockets waiting to be accepted"이다. Accept Queue에 있는 것은 handshake가 이미 끝난 연결이다.
  • accept(2): "It extracts the first connection request on the queue of pending connections", Accept Queue가 비어 있으면 "blocks the caller until a connection is present."

T1의 strace에서 accept4에 멈춰 있던 서버가 깨어난 순간은, handshake가 끝나 Accept Queue에 연결이 하나 들어온 순간이었다.

3. 직접 본다 (퀴즈를 먼저 풀고)

tools/no_accept.py는 listen(backlog=2)까지만 하고 accept를 부르지 않는다. 아래 퀴즈 1–3번을 먼저 고른 뒤 실행한다. week13/lab/teach/에서:

옆으로 밀어 보기 →

# 터미널 1: accept 안 하는 서버
python3 tools/no_accept.py

# 터미널 2 (선택, sudo): handshake 패킷 보기. 터미널 3보다 먼저 켠다
sudo tcpdump -i lo -n port 8080

# 터미널 3, 4: client 둘
nc localhost 8080

# 터미널 5: Accept Queue 보기
ss -tln 'sport = :8080'
ss -tan 'sport = :8080 or dport = :8080'

ss의 LISTEN 줄에서 Recv-Q는 Accept Queue에 쌓인 연결 수, Send-Q는 backlog다 (커널 tcp_diag.c: LISTEN이면 idiag_rqueue = sk_ack_backlog, idiag_wqueue = sk_max_ack_backlog). 연결 소켓(ESTAB)에서는 뜻이 다르다. 그 뜻은 L2에서 본다.

출력을 세션에 붙여 넣는다. 다 본 뒤 하나 더: 세 번째 nc를 붙이면 Recv-Q가 어떻게 되는지 보고, 그 숫자와 backlog를 비교한다.
